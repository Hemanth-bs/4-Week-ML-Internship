FOUR-WEEK MACHINE LEARNING INTERNSHIP — PORTAL SUBMISSION DESCRIPTIONS

WEEK 1
------
This report presents a reproducible Python-based data preprocessing workflow for machine learning using NumPy, Pandas and scikit-learn. The Wisconsin Diagnostic Breast Cancer dataset is loaded from the scikit-learn library, allowing the project to run without downloading external data. The report explains dataset inspection, dimensions, target-label preparation, data-quality checks and exploratory summaries. To demonstrate missing-value handling in a transparent and repeatable way, the script deliberately introduces missing entries into three numeric columns using a fixed random seed. Median imputation is then applied, and the report clearly distinguishes this teaching step from the original dataset. A radius-group feature is engineered from a numeric measurement, missing group labels are handled, and categorical values are converted into indicator columns using one-hot encoding. The predictor matrix is standardized with StandardScaler, and SelectKBest with an ANOVA F-test is used to demonstrate supervised feature ranking. The report records the row count, feature count, missing-value totals before and after cleaning, selected features and scaling checks. The workflow exports a cleaned CSV file and a JSON summary so the results can be reviewed or reused. The complete Python script is included with the project. The report also discusses important limitations, including the need to fit preprocessing transformations only on training data during predictive modeling to prevent data leakage. This task establishes a practical foundation for the later supervised-learning experiments.

WEEK 2
------
This report documents a supervised machine learning exercise covering both regression and classification using Python and scikit-learn. For regression, the built-in diabetes dataset is used to predict a continuous target, and Linear Regression is compared with a Random Forest Regressor. Model performance is assessed on a held-out test set using Mean Absolute Error, Root Mean Squared Error and the coefficient of determination, R-squared. For classification, the Wisconsin Diagnostic Breast Cancer dataset is used to compare a standardized Logistic Regression pipeline with a Random Forest Classifier. The data is divided into training and test partitions using a fixed random seed, and stratification is applied to preserve class proportions. Classification results include accuracy, precision, recall, F1-score and ROC-AUC, providing a more complete view than accuracy alone. The report explains the purpose of each metric and interprets the measured scores produced by the executable training script. It also discusses why scaling is included for Logistic Regression, why tree ensembles do not generally require standardization, and why a held-out test set should not be used for model fitting or repeated tuning. The code saves actual model-comparison results to a JSON file, allowing the tables in the report to be verified and regenerated. The experiments are intended as baseline comparisons rather than claims of universal model superiority. Limitations and next steps include cross-validation, systematic hyperparameter tuning, further feature engineering and evaluation against the requirements of a real application.

WEEK 3
------
This report explores unsupervised learning and model evaluation through clustering, dimensionality reduction, cross-validation and hyperparameter tuning. The Iris dataset is standardized before applying K-Means and Agglomerative Clustering with three clusters. Cluster quality is compared using the silhouette coefficient, which summarizes cohesion and separation. Adjusted Rand Index is also calculated by comparing cluster assignments with known Iris species labels after clustering; these labels are used only for post-hoc evaluation and are not supplied to the clustering algorithms. Principal Component Analysis reduces the four-dimensional standardized feature matrix to two components, and the report records the variance explained by each component and by the combined projection. The generated PCA coordinates are exported for visualization. The supervised evaluation component uses the Wisconsin Diagnostic Breast Cancer dataset and a Random Forest classifier. A stratified hold-out test set is kept separate while GridSearchCV evaluates candidate tree counts and maximum depths using five-fold stratified cross-validation on the training data. The selected estimator is assessed on the held-out test partition with accuracy, precision, recall, F1-score, ROC-AUC and a confusion matrix. The report explains the meaning of the evaluation measures, the arbitrary nature of cluster IDs, and the importance of preventing data leakage. All reported results are generated by the included executable script and saved to JSON for reproducibility. The task demonstrates that unsupervised cluster quality and supervised predictive performance are different questions and require different evaluation methods.

WEEK 4
------
This capstone report describes an end-to-end machine learning application that includes data loading, model training, held-out evaluation, model serialization and REST API development. The project uses the built-in Wisconsin Diagnostic Breast Cancer dataset from scikit-learn and divides it into stratified training and test partitions. A pipeline combines StandardScaler with Logistic Regression so the fitted preprocessing step is reused consistently at inference time. The training script calculates accuracy, precision, recall, F1-score and ROC-AUC on the held-out test set, then serializes the trained pipeline together with the ordered feature names and target labels using Joblib. A FastAPI application loads this artifact and provides root, health, feature-metadata and prediction endpoints. The prediction endpoint checks that the request contains exactly 30 finite numeric feature values, returns a class label and probabilities, and rejects malformed feature lengths with an HTTP 422 response. The implementation was tested by starting a local Uvicorn server and making real HTTP requests: the health endpoint returned status 200, the feature endpoint reported 30 inputs, a valid prediction request returned status 200, and an invalid-length request was rejected with status 422. The report includes setup commands, an architecture outline, endpoint documentation and a validation plan. It also explains production considerations such as authentication, rate limiting, dependency pinning, logging, monitoring, model versioning and input-range checks. This is an educational demonstration and explicitly not a medical diagnostic service.
